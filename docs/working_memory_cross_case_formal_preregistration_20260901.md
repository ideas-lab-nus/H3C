# Working-memory-only SZ Air and MZ Hydro formal preregistration

## Question and frozen method

This campaign tests the released H3C working-memory architecture on the remaining two BOPTEST
cases. Both arms run from the exact commit containing this preregistration and differ only through
their registered case profiles.

The method is frozen as follows:

- Baseten `deepseek-ai/DeepSeek-V4-Flash-0731` with provider-native strict structured output;
- C0 Prompt and `occupancy_routed` low thinking;
- one completed Context–Action–Outcome–Lesson record as `k=1` working memory;
- confirmed causal graph, orchestrated shared Budget and mandatory action assurance enabled;
- `--long-term-memory` absent, with zero experience/CRUD/revision/reference surface;
- unchanged P0 program, operation semantics, reward, KPI and action mapping.

No result from one arm may change the source, Prompt, controller, profile, model settings or
criteria of the other arm.

## Registered parallel arms

1. `SZ_Air`: day 203, seven-day internal warm-up, zero explicit prefix, seven formal days,
   168 Agent hours, 672 physical advances and 504 logical model calls.
2. `MZ_Hydro`: day 220, seven-day internal warm-up, zero explicit prefix, five formal days,
   120 Agent hours, 480 physical advances and 480 logical model calls.

The arms use independent worktrees, output owners, locks, Baseten session affinity values and fresh
BOPTEST test identities. They are submitted concurrently. BOPTEST `Running`/`Queued` status owns
physical capacity. Within each arm the frozen order remains Orchestrator, parallel zone Executors,
deterministic settlement, four physical advances and Reflector.

## Evidence and terminal rules

Each run records source/profile/provider/model/thinking identity, full model attempts, program
updates, actions, physical trajectory, metrics and atomic completion/failure evidence. The expected
role counts, advances, initialization, stop, fresh test identity, secret scan and physical timeline
must verify.

Initialization/advance, identity, secret or evidence corruption is a hard stop for only the affected
arm. A control-neutral mechanical defect may be repaired only through a fresh identity after the
changed-owner gates. Ordinary schema or deterministic rejection, fallback, poor comfort, poor
stability or poor reward remains adverse method evidence and does not trigger resume or a lucky
rerun.

The final report compares reward, cost, energy, zone-hours, PMV-hours, occupied peak absolute PMV,
total variation, reversals, model usage and latency with the frozen eRBC and other registered
baselines for the exact same case window. Reward is reported as the direct aggregate objective;
comfort and stability remain explicit admissibility and interpretation evidence. No paper,
LaTeX or Figure 3 changes and no additional push occur as part of the physical campaign.
