# Hydro per-rule effect projection preregistration

Date: 2026-09-02

## Decision basis

The first six-call interpreter-semantics probe from source `5db0e9e` passed every
request, Provider, finish, JSON-schema, output-envelope and secret check. It did
not pass semantic review. Two outputs contradicted the executable interpreter:

- for the occupancy-onset `anchor`, the model described `set_residual(0)` as a
  jump to the 30 C unoccupied base, although the rule itself requires current
  occupancy and therefore uses the 25 C occupied base;
- for `unoccupied_hold`, the model described `set_residual(0)` as 25 C and
  proposed `hold_setpoint` at 26.85 C as an energy-saving change, although the
  rule itself requires no current occupancy, so the existing action returns to
  the 30 C unoccupied base and the proposed hold retains more cooling.

The failed responses and requests remain immutable under
`outputs/diagnostics/hydro-interpreter-semantics-probe-20260902-5db0e9e/`.
No physical run is eligible to start from this result.

## Single method variable

The existing interpreter owner will project each current rule's action in the
binary occupancy states allowed by that rule's own `when` conditions. The model
view will show, per rule:

- first-match priority index;
- current action and resolved value;
- matching current/previous occupancy combinations;
- regime base, action formula, candidate setpoint, existing-clamp result, offset
  from that base and cooling effect;
- an explicit label when a value is only an illustration using the currently
  observed last physical setpoint.

The Executor instruction will point to the target rule's own matching-state
projection rather than the current zone regime. The facts are generated by the
same arithmetic used by physical program execution.

## Frozen boundaries

This change does not alter P0, the five parameters, the three rule actions, the
six specification operations, rule ordering, interpreter results, ProgramCheck,
causal proof, Budget, action assurance, Safety, reward, Provider settings or
acceptance criteria. It adds no runtime veto, energy threshold, cooldown,
comfort-recovery rule, case-specific condition or new operation. The eight-rule
capacity is not changed in this study.

## Offline gates

Before another external call:

1. exact regression tests must reproduce the two failed semantic cases above;
2. every projection must use the executable action arithmetic and occupancy
   conditions from the current program;
3. all historical interpreter oracle tests must remain unchanged;
4. the production renderer, compact context, bilingual examples and Prompt
   golden must be regenerated and pass freshness checks;
5. full pytest, Ruff, format, strict mypy and staged secret scan must pass;
6. P0, causal graphs, admission modules, Safety, reward and profile identities
   must remain unchanged from `5db0e9e`.

Character count is descriptive. No evidence will be removed merely to offset the
new deterministic projection.

## External validation and stop rule

A second Provider validation, if separately authorized, will use the same six
frozen Hydro evidence locations and the same one-call-per-input/no-retry policy.
The production renderer will rebuild inputs under the new source, so their hashes
and Prompt bundle identity will be new.

The validation passes only if all six responses satisfy the existing structural
contract and none contradicts the displayed target-rule base, formula, direction
or exact setpoint. The occupancy-onset `anchor` and unoccupied `unoccupied_hold`
cases are mandatory semantic gates. A structurally valid but semantically
contradictory response fails the batch.

Hydro may receive a fresh formal run/test identity only after that whole batch
passes. A failed batch causes another user review; it never launches BOPTEST.
